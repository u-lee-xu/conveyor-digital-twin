# 数字孪生传送带分拣系统 - 需求说明

## 项目背景

- **部署环境**：本地局域网电脑 / 阿里云服务器（可选）
- **限制条件**：暂无域名备案

---

## 功能需求

### 1. 手动操作模式

**基础控制功能：**
- 点击按钮控制气缸伸出/缩回
- 点击按钮投放物料
- 点击按钮启停传送带

**物理现象模拟：**
- 气缸运动过程中触发磁性开关状态变化
- 气缸伸出时，若前方有物料则将物料推出
- 物料在传送带上随传送带运动

---

### 2. 演示模式（自动演示）

**完整流程：**

```
投放物料 → 上料气缸推料 → 上料传感器检测 → 传送带启动 → 
色标传感器检测 → 分拣判断 → 气缸推出 → 流程结束
```

**分拣逻辑：**

| 物料颜色 | 色标传感器 | 物料传感器 | 分拣动作 |
|---------|-----------|-----------|---------|
| 黑色 | ✓ 检测到 | - | 分拣1气缸推出 |
| 蓝色 | ✗ 未检测到 | ✓ 检测到 | 分拣2气缸推出 |

**自动化流程：**
1. 随机投放蓝色或黑色物料
2. 上料气缸将物料推至传送带
3. 上料位置传感器检测到物料 → 启动传送带
4. 传送带带动物料前进
5. 色标传感器检测物料颜色
6. 根据检测结果，对应分拣气缸推出物料
7. 物料推出传送带后，一个完整流程结束

---

### 3. MQTT 同步模式

**适用场景**：用户拥有与数字孪生一致的实物设备（PLC、传送带、传感器、气缸、物料）

**同步要求：**

| 实物设备 | 数字孪生同步 |
|---------|-------------|
| 气缸伸出/缩回 | 3D场景气缸同步运动 |
| 传感器触发 | 3D场景传感器状态同步 |
| 磁性开关状态 | UI面板LED同步显示 |
| 传送带运行 | 3D场景传送带同步运行 |

**核心目标**：三维场景和UI面板与现场设备实时同步显示

---

### 4. MQTT 仿真模式

**适用场景**：用户无实物设备，但有PLC（实际PLC或仿真软件）

**架构方案：**
```
用户PLC → ModbusTCP → MQTT网关 → 云端/局域网 → 数字孪生页面
                    ↑                           ↓
                 反馈信号 ← ← ← ← ← ← ← ← ← ← ←
```

**功能要求：**
- 用户PLC通过ModbusTCP转MQTT连接虚拟场景
- PLC控制信号 → 虚拟产线执行动作
- 虚拟产线反馈信号（按钮、传感器等）→ PLC

**典型应用：**
- 实际控制器控制虚拟产线
- PLC程序调试与验证
- 操作培训

## 前端架构设计（状态驱动）

### 核心原则

**状态驱动，单一数据源**

```
┌─────────────────────────────────────────────────────────────┐
│                    设备状态 (Zustand Store)                  │
│                                                             │
│   conveyorRunning: boolean                                  │
│   cylinders: { feed, sorting1, sorting2 }                   │
│   sensors: { feed, color, material }                        │
│   materials: Material[]                                     │
│   magneticSwitches: { ... }                                 │
└─────────────────────────────────────────────────────────────┘
                              ▲
                              │ 写入状态
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
   ┌────┴────┐          ┌─────┴─────┐        ┌─────┴─────┐
   │ 手动模式 │          │ 演示模式   │        │ MQTT模式  │
   │ 用户点击 │          │ 状态机    │        │ 订阅消息  │
   └─────────┘          └───────────┘        └───────────┘
        
                              │ 读取状态
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      3D 渲染层                               │
│                                                             │
│   监听状态变化 → 执行动画                                    │
│   - 气缸伸缩动画                                             │
│   - 传送带滚动                                               │
│   - 物料移动                                                 │
│   - 传感器状态显示                                           │
└─────────────────────────────────────────────────────────────┘
```

### 状态管理层

```typescript
interface DeviceState {
  mode: 'idle' | 'manual' | 'demo' | 'sync' | 'sim';
  
  // 设备状态（所有模式共用）
  conveyorRunning: boolean;
  cylinders: { 
    feed: { extended: boolean };
    sorting1: { extended: boolean };
    sorting2: { extended: boolean };
  };
  sensors: { 
    feed: boolean; 
    color: boolean; 
    material: boolean;
  };
  magneticSwitches: {
    feed_extend: boolean;
    feed_retract: boolean;
    sorting1_extend: boolean;
    sorting1_retract: boolean;
    sorting2_extend: boolean;
    sorting2_retract: boolean;
  };
  materials: Material[];
  
  // 状态更新方法
  setMode: (mode: Mode) => void;
  setConveyorRunning: (running: boolean) => void;
  extendCylinder: (name: CylinderName) => void;
  retractCylinder: (name: CylinderName) => void;
  spawnMaterial: () => void;
  clearMaterials: () => void;
  reset: () => void;
}
```

### 模式切换安全机制

```typescript
function setMode(newMode: Mode) {
  // 1. 停止当前模式的活动
  //    - 演示模式：停止状态机
  //    - MQTT模式：断开连接
  
  // 2. 重置设备状态到初始值
  resetDeviceState();
  
  // 3. 切换模式
  set({ mode: newMode });
  
  // 4. 启动新模式
  //    - 演示模式：启动状态机
  //    - MQTT模式：建立连接
}
```

## 四种模式实现细节

### 模式1：手动模式

**数据流：**
```
用户点击按钮 → 更新Zustand状态 → 触发3D动画
                ↓
           物理引擎检测（碰撞、物料位置）
                ↓
           更新传感器/磁性开关状态 → UI显示
```

**需要实现：**
- 碰撞检测：气缸与物料
- 物料运动：跟随传送带
- 磁性开关：气缸位置检测

---

### 模式2：演示模式（状态机）

```
                    ┌──────────────┐
                    │   IDLE 待机   │
                    └──────┬───────┘
                           │ 启动
                           ▼
                    ┌──────────────┐
                    │  SPAWN 生成   │ ←── 随机颜色物料
                    └──────┬───────┘
                           │ 物料就位

**用户侧网关软件架构：**

```

│                                                     │
│  ┌─────────────┐    ┌─────────────┐               │

```

```

## 架构层级总结

| 层级 | 职责 | 说明 |
|------|------|------|
| **模式控制器** | 状态来源 | 不同模式有不同的状态来源，但都调用相同的状态方法 |
| **状态管理层** | 单一数据源 | Zustand Store，所有状态修改都通过这里 |
| **3D渲染层** | 状态响应 | 只读取状态，状态变化时执行动画 |

**设计优势：**
- ✅ 各模式逻辑完全隔离
- ✅ 动画代码只写一份
- ✅ 模式切换时状态可控重置
- ✅ 方便调试（状态变化可追踪）
