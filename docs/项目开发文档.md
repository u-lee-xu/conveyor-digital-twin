## 1. 项目概述

### 1.1 项目简介

数字孪生传送带分拣系统是一个基于React + Three.js + Electron + ModbusTCP的工业数字孪生应用。该系统通过3D建模真实还原传送带分拣设备，并支持与真实PLC进行通信，实现虚实联动。

### 1.2 主要功能

| 功能模式 | 描述 |
|---------|------|
| **手动模式** | 用户可直接控制气缸、传送带，投放物料进行演示 |
| **演示模式** | 系统自动运行完整的分拣流程，无需用户操作 |
| **评分模式** | 用于测试和评估PLC程序，自动记录操作并评分 |
| **仿真模式** | 与真实PLC进行闭环控制，数字孪生作为虚拟设备 |

### 1.3 应用场景

- 工业自动化教学实训
- PLC程序开发调试
- 设备演示和展示
- 远程监控和操作

## 4. 核心模块详解

### 4.1 状态管理模块 (stores/)

#### 文件：useDeviceStore.ts

**功能**：使用Zustand管理整个系统的设备状态

**核心状态**：
- `mode`: 当前运行模式
- `conveyorRunning`: 传送带运行状态
- `cylinders`: 三个气缸的状态
- `sensors`: 三个传感器的状态
- `material`: 物料状态
- `score`/`penalties`: 评分系统状态

**核心方法**：
```typescript
- setMode(mode)              // 设置运行模式
- toggleConveyor()          // 切换传送带
- extendCylinder(name)      // 伸出气缸
- retractCylinder(name)     // 缩回气缸
- spawnMaterial()           // 生成物料
- clearMaterial()           // 清除物料
- setSensor(name, active)   // 设置传感器状态
- updateMaterialPosition(pos) // 更新物料位置
```

**文件依赖关系**：
- 依赖：`../types` (类型定义)
- 被依赖：`App.tsx`, `usePhysics.ts`, `useDemoMode.ts`, `useScoring.ts`, `useSimMode.ts`, 多个组件

### 4.3 自定义Hooks模块 (hooks/)

#### 文件：usePhysics.ts

**功能**：物理模拟Hook，处理物料运动、碰撞检测、传感器触发

**核心逻辑**：

1. **传送带运动**：物料在传送带上随传送带移动
2. **气缸碰撞**：气缸推动物料产生Z轴方向运动
3. **惯性模拟**：物料被推动后有惯性，逐渐减速
4. **传感器检测**：根据物料位置更新传感器状态
5. **边界检查**：物料超出边界时自动清除

**时间缩放**：
- 以60fps为基准进行时间缩放
- 限制最大时间缩放防止突变

**文件依赖关系**：
- 依赖：`../stores/useDeviceStore`, `../types`, `../components/scene/shared/constants`
- 被依赖：`App.tsx`

---

#### 文件：useDemoMode.ts

**功能**：演示模式Hook，自动运行完整分拣流程

**状态机**：
- `idle`: 空闲状态
- `feed`: 上料阶段
- `wait`: 等待阶段
- `sort`: 分拣阶段
- `reset`: 复位阶段

**文件依赖关系**：
- 依赖：`../stores/useDeviceStore`
- 被依赖：`App.tsx`

---

#### 文件：useScoring.ts

**功能**：评分模式Hook，用于测试和评估PLC程序

**评分规则**：
- 初始满分100分
- 根据错误类型扣除相应分数
- 记录所有通过项和扣分项

**文件依赖关系**：
- 依赖：`../stores/useDeviceStore`
- 被依赖：`App.tsx`

#### 文件：useSimMode.ts

**功能**：仿真模式Hook，处理与PLC的Modbus通信

**核心功能**：
- 连接/断开ModbusTCP服务器

**文件依赖关系**：

### 4.4 服务层模块 (services/)

#### 文件：modbus-websocket.ts

**功能**：Modbus服务类，通过WebSocket与代理服务器通信

**核心方法**：
```typescript
- connect(host, port)              // 连接Modbus服务器
- disconnect()                     // 断开连接
- readCoils(address, length)       // 读取线圈
- writeCoil(address, value)        // 写入单个线圈
- writeCoils(address, values)      // 批量写入线圈
- writeFeedbackBatch(data)         // 批量写入反馈信号
- readAllControlSignals()          // 读取所有控制信号
- writeFeedSensor(active)          // 写入上料传感器状态
- writeColorSensor(active)         // 写入色标传感器状态
- writeMaterialSensor(active)      // 写入物料传感器状态
- writeMagneticSwitch(name, extended)  // 写入磁性开关状态
```

**自动重连**：WebSocket断开后5秒自动尝试重连

**文件依赖关系**：
- 依赖：浏览器WebSocket API
- 被依赖：`../hooks/useSimMode.ts`

### 4.5 WebSocket代理服务器 (websocket-server/)

#### 文件：server.js

**功能**：Node.js代理服务器，桥接WebSocket和ModbusTCP

**架构**：
```
浏览器(WebSocket:8081) <-> Node.js代理 <-> PLC(ModbusTCP:502)
```

**核心类**：`SimpleModbusTCP`

**关键功能**：
- 原生实现ModbusTCP协议（不依赖第三方库）
- 正确处理TCP粘包和分包问题
- 支持请求超时机制
- 使用事务ID（Transaction ID）匹配请求和响应

**支持的Modbus功能码**：
- FC 0x01: 读取线圈
- FC 0x05: 写入单个线圈
- FC 0x0F: 写入多个线圈

**消息类型**：
```javascript
- 'connect'      // 连接Modbus服务器
- 'disconnect'   // 断开连接
- 'read-coils'   // 读取线圈
- 'write-coil'   // 写入单个线圈
- 'write-coils'  // 批量写入线圈
- 'get-status'   // 获取连接状态
```

**文件依赖关系**：
- 依赖：`ws`, `net` (Node.js内置)
- 独立运行，不被其他前端文件依赖

## 5. 数据流程

### 5.1 手动模式数据流

```
用户操作 -> UI组件 -> useDeviceStore -> 3D组件渲染
                   ↓
              usePhysics -> 更新物料位置 -> 触发传感器
```

### 5.2 仿真模式数据流

```
PLC (控制信号)
    ↓ ModbusTCP
WebSocket代理服务器
    ↓ WebSocket
ModbusService (modbus-websocket.ts)
    ↓
useSimMode
    ↓
useDeviceStore
    ↓
3D组件渲染 + usePhysics物理模拟
    ↓
传感器/磁性开关状态更新
    ↓
ModbusService写入反馈
    ↓ WebSocket
WebSocket代理服务器
    ↓ ModbusTCP
PLC (读取反馈)
```

### 5.3 评分模式数据流

```
useScoring监控设备状态
    ↓
检测操作序列
    ↓
判断是否符合规则
    ↓
更新分数和记录
    ↓
ScoringPanel显示结果
```

## 6. Modbus通信协议

### 6.1 Modbus地址映射表

| 地址 | 功能 | 类型 | 方向 |
|------|------|------|------|
| 0 | 启动信号 | 线圈 | PLC → 孪生 |
| 1 | 复位信号 | 线圈 | PLC → 孪生 |
| 2 | 上料气缸缩回限位 | 线圈 | 孪生 → PLC |
| 3 | 上料气缸伸出限位 | 线圈 | 孪生 → PLC |
| 4 | 分拣气缸1缩回限位 | 线圈 | 孪生 → PLC |
| 5 | 分拣气缸1伸出限位 | 线圈 | 孪生 → PLC |
| 6 | 分拣气缸2缩回限位 | 线圈 | 孪生 → PLC |
| 7 | 分拣气缸2伸出限位 | 线圈 | 孪生 → PLC |
| 8 | 上料传感器 | 线圈 | 孪生 → PLC |
| 9 | 色标传感器 | 线圈 | 孪生 → PLC |
| 10 | 物料传感器 | 线圈 | 孪生 → PLC |
| 100 | 上料气缸阀 | 线圈 | PLC → 孪生 |
| 101 | 分拣气缸1阀 | 线圈 | PLC → 孪生 |
| 102 | 分拣气缸2阀 | 线圈 | PLC → 孪生 |
| 103 | 传送带 | 线圈 | PLC → 孪生 |

### 6.2 通信时序示例

**分拣流程时序**：
```
1. PLC写入地址0=1 (启动)
2. 孪生系统检测启动信号
3. PLC写入地址100=1 (上料气缸伸出)
4. 上料气缸伸出，到达限位后孪生写入地址3=1
5. PLC检测到地址3=1，写入100=0 (缩回)
6. 上料气缸缩回，到达限位后孪生写入地址2=1
7. 物料被推上传送带，上料传感器触发(地址8=1)
8. PLC写入103=1 (传送带运行)
9. 物料到达色标传感器...
10. 根据颜色分拣...
```

## 8. 部署说明

### 8.1 Web版本部署

1. 构建前端：`npm run build`
2. 将`dist/`目录部署到Web服务器
3. 需要同时运行WebSocket服务器

### 8.2 Electron桌面应用部署

1. 构建应用：`npm run electron:build:win`
2. 在`release/`目录找到安装包
3. 分发安装包给用户

- WebSocket服务器需要可被前端访问
- ModbusTCP服务器地址需要可被WebSocket服务器访问
- 防火墙需要开放相应端口（8081用于WebSocket，502用于ModbusTCP）

## 附录

### A. 常见问题

**Q: WebSocket连接失败怎么办？**
A: 检查`websocket-server/server.js`是否正在运行，确认端口8081未被占用。

**Q: 如何修改3D场景的视角？**
A: 在Scene.tsx中修改camera.position.set()的参数。

**Q: 如何添加新的气缸或传感器？**
A: 首先在types中添加定义，然后在useDeviceStore中添加状态，最后创建3D组件。
